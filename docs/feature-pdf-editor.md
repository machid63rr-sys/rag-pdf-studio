# 機能① MD/HTML → PDF

MarkdownまたはHTML(+CSS)を取り込み、プレビューを見ながら編集し、**元のファイルとPDFを同時に出力**する機能です。
別リポジトリの単体アプリ md-pdf-editor(コミット `fead8e7`)を、そのままコピーして、機能①として組み込んだものです。
この文書は、機能①の使い方と仕様をまとめたもの(コピー元のREADMEを、このアプリに合わせて直したもの)で、**起動方法は、リポジトリ直下の [README.md](../README.md)** を参照してください。

## 起動

リポジトリ直下の [README.md](../README.md) の手順(`docker compose up`)で、他の機能(② PDF → OCR → MD、③ RAG)と一緒に起動します。
ブラウザで **http://localhost:8090** を開き、「① MD/HTML → PDF」のタブを使います(Chrome または Edge)。

> WSL2 上で動かしている場合も、Windows のブラウザから `http://localhost:8090` で開けます。

## 使い方

1. **取り込み**: 次のどれかで取り込みます。UTF-8以外のファイルは、文字化けさせずにエラーにします。
   - **フォルダごと(おすすめ)**: フォルダをドラッグ&ドロップ、または「フォルダを選択」。文書(Markdown / HTML)が参照している**CSS・画像を、フォルダ内の位置のとおりに自動で読み込みます**(`images/a.png`、`../css/style.css` なども、書かれたとおりに探します)。フォルダにMarkdown・HTMLが複数あるときは、開くファイルを選びます。隠しファイル(`.git` など)と `node_modules` は読みません。フォルダが大きすぎる(5000ファイル超)場合は、取り込みません。
   - **ファイルを個別に**: Markdown(.md / .markdown / .txt)またはHTML(.html / .htm)を、ドラッグ&ドロップ、または「ファイルを選択」。HTMLのCSS(.css)・画像(.png / .jpg / .gif / .webp / .svg)も一緒に複数選択します。フォルダ構成が分からないため、参照は**ファイル名**で突き合わせます(例: `images/a.png` と書かれていれば、選んだ `a.png`。同じ名前が複数あると決められないため、使いません)。
   - **貼り付け**: Markdown / HTMLを選んで貼り付けます(CSS・画像は読み込めません)。
   - 取り込める文書は1つです(個別に選ぶ場合に、HTMLが2つ、Markdownと一緒にCSS、などはエラーにします)。
2. **編集(Markdown)**: 「プレビュー(書式付きで編集)」で、見出し・表・箇条書き・コードを見た目のまま編集できます。「Markdown」タブでは、元のMarkdownを直接編集できます。タブを切り替えると、編集内容が引き継がれます。
   **編集(HTML・CSS)**: 次の3種類のタブで編集できます。
   - 「プレビュー(直接編集)」: 表示を見ながら、文字を直接編集できます。上のボタンで、元に戻す・太字・斜体・下線・見出し・段落・箇条書きも使えます。**編集した箇所のHTMLだけが書き換わり、編集していない部分は、取り込んだまま(インデント・引用符・実体参照・コメントなど)です**。貼り付けは、他のページの書式を持ち込まないよう、文字だけになります。
   - 「HTML」「CSS: ファイル名」: ソースを直接編集します。隣のプレビューに、入力内容がすぐ反映されます。
   - タブを切り替えると、編集内容が引き継がれます。表の行や列の追加など、プレビューでできない操作は、「HTML」タブで行ってください。
   **自動保存**: 編集内容は、編集が止まって1.5秒ほどたつと、**このブラウザに自動で保存**されます(画面に「自動保存: このブラウザに保存しました」と出ます)。誤ってタブを閉じたり、再読み込みしたりしても、次に開いたとき、取り込み画面に「前回の編集内容が残っています」と出て、**「続きから再開」**で戻せます(「破棄」で消せます)。詳しくは、下の「下書きの自動保存と復元」を見てください。
3. **出力**: 「保存するファイル」で、保存するものをチェックで選びます(Markdownなら Markdown (.md) と PDF (.pdf)、HTMLなら HTML (.html)・CSS(取り込んだファイルごと)・PDF (.pdf))。先にファイル名(拡張子なし)を決めてから、保存します。保存方法は次の2つで、1つだけ保存する場合も同じです(保存されるのは、チェックしたファイルだけです)。CSSは、HTMLの `<link>` が指している位置(HTMLのフォルダからの相対パス。例: `css/style.css`)に保存します(ファイル名の指定は、CSS以外に使います)。画像は、元のファイルが手元にあるため、保存しません。
   - **選んだフォルダへ出力**: 「出力先フォルダを選択」→「選んだフォルダへ…を出力」(両方なら「MDとPDF」、片方なら「MD」または「PDF」)。好きなフォルダに直接書き込みます。保存するファイルと同名のファイルがある場合は、上書きするか確認します。
   - **ダウンロードで保存**: ブラウザのダウンロードとして保存されます(保存先はブラウザの設定に従います)。フォルダ選択の制限を受けず、どのブラウザ・どの接続方法でも使えます。複数ファイルのダウンロードを確認されたら、許可してください。ダウンロードでは、サブフォルダを作れないため、CSSはファイル名だけで保存されます(HTMLが `css/style.css` を指している場合は、フォルダへ出力を使ってください)。

   「PDFを生成して確認(新しいタブ)」で、出力前にPDFの見た目を確認できます。

## 動作環境と制約

- **「選んだフォルダへ出力」は Chrome / Edge 限定**です(ブラウザのFile System Access APIを使うため)。Firefox・Safari では、このボタンが無効になり理由が表示されます。その場合は「ダウンロードで保存」を使ってください。
- 取り込みの「フォルダを選択」とフォルダのドロップは、Chrome・Edge・Firefox・Safariで使えます(ブラウザが「ファイルをアップロードしますか?」と確認することがあります。ファイルは、このPCのアプリにだけ渡り、外部へ送られません)。
- **`http://localhost:ポート` でアクセス**してください。`http://192.168.x.x:ポート` のようなIPアドレスでのアクセスでは、ブラウザの仕様でフォルダ選択が使えません(「ダウンロードで保存」は使えます)。別のPCで動かしているコンテナを使う場合は、SSHのポート転送(`ssh -L 8090:127.0.0.1:8090 <ホスト>`)で、手元の `localhost:8090` から開くと、フォルダ選択も使えます。
- Chrome / Edge は、システムデータを含むフォルダ(`ドキュメント` / `ダウンロード` / `デスクトップ` のフォルダそのもの、ホームフォルダ、`AppData` など)を、出力先として選ぶことを拒否します(「システムデータが含まれているため…」と表示されます)。これはブラウザのセキュリティ機能で、アプリからは解除できません。次のどちらかで保存してください。
  - その中に**新しいフォルダを作って**、そのフォルダを選ぶ(例: `ドキュメント` の中に `md-pdf` フォルダを作る)
  - 「ダウンロードで保存」を使う
- 認証機能はありません。既定ではこのPCからのみ接続できます(`BIND_ADDR`)。

## PDF・Markdownの扱い

- PDFはサーバ側のChromiumで、Markdownから、下の「ページ設定」に従って生成します(既定はA4縦、余白は上20mm・下25mm・左右20mm、フッターにページ番号)。日本語はNoto Sans CJK JPの字形です。プレビューはお使いのOSのフォントで描画されるため、字形や折り返し位置が少し異なることがあります(ページの区切りは、下の「ページの区切りの表示」のとおり、PDFと同じ条件で測った位置を、プレビューに重ねて表示します)。
- **生HTML**(`<br>`、`<div>`、`<!-- コメント -->` など)は、実行も削除もせず、**文字としてそのまま表示**されます(`<img>` のタグと、手動の改ページの印だけは、下のとおり扱います)。出力前に画面に警告が出ます。
- **画像**は、`data:image/…;base64,…`(png・jpeg・gif・webp・svg)と、**取り込んだ画像**(`![図](images/a.png)` のような相対パス。フォルダごと取り込んだ場合は、Markdownのフォルダを基準に解決)が、エディタとPDFに表示されます。それ以外(外部のURL・取り込んだ中に無いもの)は `[画像: 代替文](URL)` という文字になります(外部へは通信しません)。出力前に警告が出ます。Markdownの本文は書き換えません(画像のパスはそのまま保存されます)。SVGは `<img>` として表示するため、スクリプトは実行されず、外部のファイルも読み込まれません。
- **コードブロック**は、言語名(```` ```python ````、```` ```js ```` など)に応じて**構文ごとに色分け**されます。エディタでは、コードブロックの右上で言語を選べます。PDFは、約190言語(Python・JavaScript・TypeScript・Bash・SQL・Java・C#・C++・Go・Rust・Ruby・PHP・Kotlin・Swift・PowerShell・Dockerfile・YAML・JSON・HTML・CSS・Diff など)に対応し、`py`・`js`・`sh` のような別名も使えます。言語名の無いコードブロック、`text` / `txt`、未対応の言語名は、色分けせずそのまま表示します。10万文字を超える長いコードは、色分けせずに表示します。
- **Mermaid の図**: 言語名を `mermaid` にしたコードブロックは、エディタではコードの下に図を表示し、PDFでは図として出力します(フローチャート・シーケンス図・ガントチャート・円グラフなど、Mermaidが対応する図)。**PDFに何を出すかは、コードブロックごとに選べます**: 「図のみ」(既定)・「コードのみ」・「コードと図」(コードの下に図)。エディタの各ブロックの下にある「PDFでの表示」で選ぶと、言語名の後ろに `show=code` / `show=both` と書き込まれます(「図のみ」は何も書きません)。Markdownに手で書いてもかまいません(例: ` ```mermaid show=both `)。言語名の後ろの文字は、ほかのMarkdownツールでは無視されます。エディタでは、編集しやすいよう、選択に関わらずコードと図の両方を表示します。Markdownに保存されるのは、コードと、この選択だけです。図が描けない(構文の誤りなど)ときは、エディタに理由を表示し、PDFには「描画できなかったため、コードのまま表示します」という理由とコードを入れます(PDFの生成は続けます)。「コードのみ」の図は、描画しません。図は1つの文書で30個までで、超えた分はコードのまま表示します。図の文字に含まれるHTMLやスクリプトは実行されず、図の描画でも外部へは通信しません。図があるPDFは、図の描画のために、生成に1秒ほど余分にかかります。
- **ページ設定**: 編集画面の「ページ設定」で、PDFの用紙・向き・余白・ページ番号を選べます。出力するPDFと、ページの区切りの表示(赤い点線)の両方に反映されます。
  - 用紙: A4(既定)・A3・B5・B4・Letter。向き: 縦(既定)・横。
  - 余白: 標準(上20mm・下25mm・左右20mm。既定)・狭い(上10mm・下15mm・左右10mm)・広い(上25mm・下30mm・左右25mm)。ミリ単位の自由入力はありません(Chromiumが用紙・余白を整数のポイントへ丸めて印刷するため、本文の大きさを、プリセットごとに実測して、ページの区切りの表示をPDFと一致させています)。
  - ページ番号: フッターに「1 / 3」を付けるか。外しても、余白は変わりません。
  - 設定は、ブラウザに覚えておき、次に開く文書も、前回の設定で始まります(保存できないブラウザでは、毎回、既定で始まります)。Markdownには書き込みません。
  - 縦長のMermaidの図は、用紙・向き・余白に合わせて、1ページに収まる大きさに縮めます。
  - **HTMLを取り込んだ文書**では、用紙・向き・余白を、文書のCSS(`@page`)が決めるため、選べるのは「ページ番号」だけです。元のHTMLは書き換えません。
- **ページの区切りの表示**: 「プレビュー(書式付きで編集)」には、PDFのページが切り替わる位置が、赤い点線と「2ページ目」などの表示で、**常に**重なって表示されます(エディタの下に、全ページ数も表示されます)。PDFを出力しなくても、どこで改ページされるかを確認できます。
  - 位置は、PDFを作るのと同じChromium・同じフォント・同じ用紙と余白(「ページ設定」どおり)で、サーバが測ったものです。ページ設定を変えると、測り直されます。見出しの直後で改ページしない、表の行を途中で切らない、表の見出し行を各ページで繰り返す、といったPDFの改ページの規則も、そのまま反映されます。
  - 線は、「どの内容の前で、次のページになるか」で位置を決めます。プレビューは、画面の幅やフォントがPDFと違い、文字の折り返しが異なりますが、同じ文・同じ表の行・同じコードの行の前に、線が入ります(プレビューの折り返しの途中の文で改ページする場合は、その行の下に線が入ります)。
  - 空行(空の段落)が、ページの上端に残る場合(空行の途中でページが替わる場合)は、線は、入力した文字の直前ではなく、PDFと同じく、その空行の前に入ります(PDFでは、ページの上端に、空行の分の空きが残るため)。
  - 編集が止まって0.7秒ほどたつと、サーバに測り直してもらいます。測り直す間(1〜2秒)は、線が薄くなり、「測り直し中…」と表示されます。サーバに接続できないときは、線は更新されず、理由が表示されます(編集・出力には影響しません)。
  - 測定のために、画像のデータは送りません(同じ大きさの空の画像に置き換えて送ります)。Mermaidの図は、一度描いたものを覚えておくため、測り直しのたびに描き直しません。
  - 「Markdown」タブ(テキスト欄)には、表示されません。HTMLを取り込んだ場合のプレビューにも、まだ表示されません(HTMLは、文書のCSSで、用紙の大きさ・余白・幅が変わるため、別の対応が必要です)。
- **手動の改ページ**: 「プレビュー(書式付きで編集)」のツールバーの「改ページ」で、カーソルの位置に、改ページの区切り(「─ 改ページ ─」の表示)を入れられます。PDFでは、その位置から新しいページになります。Markdownには、多くのMarkdown→PDFツール(VS Code・Typora など)が改ページとして扱う、次の1行が、独立したブロックとして保存されます。「Markdown」タブに、手で書いてもかまいません(前後は空行で区切ってください)。
  ```html
  <div style="page-break-after: always"></div>
  ```
  - 段落の途中に入れると、そこで段落が2つに分かれます。段落の先頭・末尾や空の段落に入れた場合は、空の段落は残りません(PDFで、ページの先頭に空行ができないようにするためです)。区切りは、「削除」ボタンで消せます。
  - 改ページとして扱うのは、**文書の直下**にある、中身が空で、属性が `style` だけの `<div>` で、`style` が `page-break-after: always`(または `break-after: page`)のものだけです。リスト・引用の中や、段落の途中に書いたものは、文字のまま表示します(「生HTML」のとおり)。
  - 区切りが連続すると、空のページができます。文書の最後の区切りは、空のページを作りません。
  - ページの区切りの表示(赤い点線)も、改ページを含めて測るため、区切りの直後に出ます。
- **画像のドラッグ&ドロップ(埋め込み)**: 画像ファイル(PNG・JPEG・GIF・WebP・SVG。1枚10MBまで)を編集欄へドロップすると、画像のデータ(`data:` URI)を、文書の中へそのまま埋め込みます。「プレビュー」では、ドロップした位置に画像が入ります(文の途中なら、そこで文が分かれます)。「Markdown」タブでは、カーソルの位置(範囲を選択していれば、その範囲の代わり)に `![ファイル名](data:image/…)` が入り、段落が壊れないよう前後が空行で区切られます。クリップボードの画像(スクリーンショットなど)を貼り付けても、同じように埋め込まれます。画像以外のファイル・大きすぎる画像は、理由が表示され、文書は変わりません(ブラウザがそのファイルを開いて、編集内容が失われることもありません)。画像のデータが、Markdownの文字として入るため、文書が大きくなります(画像の約1.3倍。画面に、増える大きさが表示されます)。文書と合わせて30MBまでです(`MAX_MARKDOWN_BYTES`)。画像を別のファイルのまま使いたい場合は、フォルダごと取り込んで、`![図](images/a.png)` のように参照してください。
- **画像の大きさを変えた場合**: エディタで画像の大きさを変えると、Markdownには `![]()` ではなく、`<img src="…" width="300" height="166" />` というタグで保存されます(Markdownの画像記法には、大きさを書く方法が無いためです)。**この `<img>` のタグだけは、画像として表示します**(手で書いてもかまいません)。使うのは `src`・`alt`・`title`・`width`・`height` だけで、`style`・`onerror` などの属性は無視します(出力しません)。`width`・`height` は、数字か「50%」の形だけ有効です。画像の扱い(data URI・取り込んだ画像・表示できない画像は文字になる)は、`![]()` と同じです。`<img>` 以外のHTMLや、`<img>` に文字・ほかのタグが混ざるものは、上の「生HTML」のとおり、文字として表示します。
- リンクは http / https / mailto / tel と相対URLだけ有効です。`javascript:` などは `文字 (URL)` になります。
- 先頭の **front matter**(YAML)は、PDFにYAMLのコードブロックとして表示されます。
- 段落内の改行は、すべて改行として扱います(プレビューの表示と揃えるため)。
- 表として成立しない「|」付きの行がある場合は、警告が出ます。

### HTMLの扱い

- PDFは、MarkdownのときのようなアプリのCSSは使わず、**取り込んだHTMLとCSSの見た目のまま**になります(CSSは、HTMLの `<link>` の位置に埋め込んでから描画します。参照する `<link>` が無いCSSは、`<head>` の末尾に追加して適用します。保存する `.html` には埋め込みません)。
- 用紙は既定でA4縦(余白20mm、フッターにページ番号)です。CSSの `@page { size: A5 landscape; }` などで用紙サイズを指定すると、それに従います。画面の「ページ設定」では、フッターのページ番号を付けるかどうかだけを選べます(用紙・向き・余白の設定は、HTMLでは使いません。HTMLは書き換えません)。
- **JavaScriptは実行しません**(プレビュー・PDFとも)。`<script>` やイベント属性(`onclick` など)は動かず、JavaScriptで作られる内容は表示されません。`<noscript>` の内容は、そのまま表示されます。
- **外部へは通信しません**。`http(s)://` のURLの画像・CSS・Webフォントは、表示されません。出力前に警告が出ます。`<meta http-equiv="refresh">`(自動で別ページへ移動)は、無視します。
- **取り込んだ画像は表示されます**。`<img src>`・`srcset`・`<video poster>`・`style` 属性・`<style>`・取り込んだCSSの `url(…)` が指す画像が、取り込んだファイルの中にあれば、プレビューとPDFに表示されます(CSS内の相対パスは、そのCSSのフォルダを基準にします)。表示のためだけの処理で、保存するHTML・CSSの画像のパスは書き換えません。取り込んだ中に無い画像、画像以外のファイル(フォント・動画など)、CSSの `@import` は、表示・読み込みされず、警告が出ます(フォントは `data:` のURIにすると使えます)。
- **画像のドラッグ&ドロップ(埋め込み)**: 画像ファイルをドロップすると、画像のデータ(`data:` URI)を埋め込みます。プレビューでは、ドロップした位置に `<img src="data:…" alt="ファイル名">` が入り、HTMLには、その画像の分だけが加わります(ほかの部分は、取り込んだままです)。「HTML」タブではカーソルの位置に `<img>` を、「CSS」タブでは `url("data:…")` を挿入します。画像以外のファイル・大きすぎる画像(10MB超)は、理由が表示され、文書は変わりません。
- 画像は、PDF生成のためにサーバへ送ります(`data:` URIにするため、元のファイルの約1.3倍になります)。文書と合わせて30MBまでです(`MAX_MARKDOWN_BYTES`)。
- 文字は、サーバ側のフォント(Noto Sans CJK JPなど)で描画されます。`font-family` で指定したフォントがサーバに無い場合は、代わりのフォントになります(Webフォントは `data:` のURIで埋め込んだ場合だけ使えます)。
- UTF-8のHTMLだけ取り込めます。Shift_JISなどのHTMLは、UTF-8に変換してから取り込んでください(`<meta charset>` の宣言とファイルの文字コードが食い違うと、文字化けするため)。
- プレビューでの編集は、編集後の表示をブラウザが解釈し直した内容を、元のHTMLと見比べて、違う部分だけを書き換えます。段落の分割(Enter)・太字などで構造が変わった場合は、その段落(の範囲)のHTMLが、ブラウザの出力する形(属性は二重引用符、`&nbsp;` など)に変わります。それ以外の部分は変わりません。

### 下書きの自動保存と復元

- **保存するもの**: 編集中の文書(Markdown、またはHTMLとCSSの編集内容)、元のファイル名、ページ設定。編集が止まって1.5秒ほどたつと、ブラウザのIndexedDB(このPCの、このブラウザの中だけ。外部へは送りません)に保存します。保存先は1つで、最新の下書きだけを残します(30MB近い文書でも、保存で画面が止まる時間は、0.05秒以下です)。
- **保存しないもの**: フォルダから取り込んだ**画像・CSSのファイル**(復元後は、画像が「見つからない」警告になります。元のフォルダを取り込み直してください。ドロップして埋め込んだ画像は、文書の中に入っているため、復元されます)。取り込んだままで、編集していない文書も、保存しません。編集を元に戻して、取り込んだままの内容になったときは、保存した下書きを消します。
- **再開と破棄**: 画面を開き直すと、取り込み画面に、ファイル名と保存した日時が出ます。「続きから再開」で、編集内容とページ設定が戻ります。再開した文書は、元のファイルが無いため、**常に「変更あり」として扱い**、別のファイルを読み込むときに確認します(続けると、下書きも消えます)。新しいファイルを開いて編集を始めると、その下書きは、新しい内容に置き換わります(複数の下書きは、持ちません。複数のタブで開いたときは、最後に保存した内容が残ります)。
- **タブを閉じる前の警告**: 保存していない編集があるとき(編集の直後の1.5秒ほどと、保存に失敗したとき)だけ、ブラウザの「このサイトを離れますか?」の警告を出します。保存できなかったとき(容量不足・プライベートウィンドウなど)は、画面に理由を出します。その場合は、タブを閉じる前に、必要な内容を出力してください(編集と出力は、そのまま使えます)。

### 空行(空の段落)

- 書式付きエディタで、Enterを重ねて作った**空行(空の段落)は、PDFでも、その数だけ1行分の空きになります**。Markdownでは、空の段落は、`&nbsp;`(改行しない空白)だけの段落として保存されます(例: `最初の段落\n\n&nbsp;\n\n&nbsp;\n\n次の段落`)。エディタに読み込み直す(「Markdown」タブから「プレビュー」に戻る・ファイルを開き直す)と、空の段落に戻り、文字を入力しても、先頭に見えない空白は残りません。
- 空行が重なっただけのMarkdown(`最初の段落\n\n\n\n次の段落`)は、Markdownの規則どおり、**1つの段落の区切りにまとまります**(PDFでも、エディタでも)。「Markdown」タブで空きを入れたいときは、`&nbsp;` だけの行を書いてください。
- 段落の中の改行(**Shift+Enter**)は、1つだけなら、ふつうの改行として保存されます。**2つ以上続けて押した場合は、行末に `\` を付けた改行(Markdownの強制改行)として保存されます**(例: `最初の段落\`・`\`・`\`・`次の文` の4行)。ふつうの改行のまま保存すると、Markdownでは空行(別の段落)になり、プレビューでは1つの段落なのにPDFでは2つの段落になってしまうためです。強制改行にしておくと、プレビューとPDFで、改行の数が一致します。
- コードブロックの中の空行は、そのままです。文書の末尾の空の段落は、保存しません(表やコードで終わる文書では、エディタが、末尾に空の段落を自動で置くことがあるため。見た目には影響しません)。

### 書式付きで編集したときの正規化(Markdown)

「プレビュー」で**一度でも編集すると、Markdown全体の書き方が正規化**されます。内容(文字)は保たれますが、書き方は次のように変わります。編集しなければ、取り込んだMarkdownはそのまま出力されます。

- 箇条書きの記号は `*`、水平線は `***`、強調は `**太字**` / `*斜体*` になる
- 番号付きリストの開始番号は1始まりになる(`3.` から始めても `1.` になる)
- 表の桁が揃えられる
- Setext見出し(`===` の下線)はATX見出し(`#`)になる。`~~~` のコードフェンスは ``` になる
- インデントによるコードブロックは、通常の段落になる
- 行末の強制改行マーカー(行末の空白2つ・`\`)は消える(改行そのものは残る)
- HTMLエンティティ(`&amp;` など)は文字に戻る。裸のURLはリンク記法になる
- 元から `\<` と書かれていた箇所は `<` になる

### 書式付きで扱えない記法

**脚注**(`[^1]`)と**参照形式のリンク**(`[文字][id]` + `[id]: URL`)は、書式付きエディタが解釈できません。含まれている場合は、その旨を表示して「Markdown」タブへ切り替わります。PDFは通常どおり出力できます。

## 設定

リポジトリ直下の `.env`(`.env.example` をコピー)で設定します。機能①に関わる変数は次のとおりです(すべて省略可能)。OCR・RAGの設定は、直下のREADMEを参照してください。

| 変数 | 既定値 | 内容 |
| --- | --- | --- |
| `HOST_PORT` | `8090` | ブラウザで開くポート番号 |
| `BIND_ADDR` | `127.0.0.1` | 接続を受け付けるアドレス。LAN内の他のPCにも公開する場合は `0.0.0.0`(認証が無いため信頼できるネットワークのみ) |
| `MAX_MARKDOWN_BYTES` | `31457280` | 受け付けるMarkdown・HTMLの最大サイズ(バイト)。文書に含まれる画像も、この大きさに数えます(画像は、元のファイルの約1.3倍になります) |
| `PDF_TIMEOUT_MS` | `60000` | PDF生成のタイムアウト(ミリ秒) |

## API

画面を使わずに、PDFだけ生成することもできます。`markdown` または `html` のどちらか一方を指定します。

```bash
curl -X POST http://localhost:8090/api/pdf \
  -H 'Content-Type: application/json' \
  -d '{"markdown": "# 見出し\n\n本文"}' \
  -o out.pdf

# Markdownに、相対パスの画像を添える(baseDir: Markdownのフォルダ、assets: 「パス」→「data URI」。パスは、baseDirを基準に解決した書き方)
curl -X POST http://localhost:8090/api/pdf \
  -H 'Content-Type: application/json' \
  -d '{"markdown": "![図](img/a.png)", "baseDir": "docs", "assets": {"docs/img/a.png": "data:image/png;base64,iVBORw0KGgo…"}}' \
  -o out.pdf

# HTML(CSS・画像は、<style> と data: URI で埋め込んだもの。外部ファイルは読み込まれません)
curl -X POST http://localhost:8090/api/pdf \
  -H 'Content-Type: application/json' \
  -d '{"html": "<!DOCTYPE html><style>h1{color:#c00}</style><h1>見出し</h1><p>本文</p>"}' \
  -o out.pdf

# ページ設定(省略可。paper: A4・A3・B5・B4・Letter / orientation: portrait・landscape / margin: standard・narrow・wide / pageNumbers: true・false。
# 4つの項目をすべて指定します。HTMLでは、pageNumbers だけが使われます)
curl -X POST http://localhost:8090/api/pdf \
  -H 'Content-Type: application/json' \
  -d '{"markdown": "# 見出し\n\n本文", "pageSettings": {"paper": "A3", "orientation": "landscape", "margin": "narrow", "pageNumbers": false}}' \
  -o out.pdf
```

PDFにしたときの、ページの区切り位置だけを測ることもできます(Markdownだけ。画面が、プレビューへの表示に使います。リクエストは `/api/pdf` と同じで、`pageSettings` も指定できます)。

```bash
curl -X POST http://localhost:8090/api/layout \
  -H 'Content-Type: application/json' \
  -d '{"markdown": "# 見出し\n\n長い本文…"}'
# => {"pages": 3, "starts": [{"page": 2, "block": 7, "tag": "p", "kind": "text", "offset": 136, "snippet": "の、少し長めの文章を繰り"}, …]}
```

`starts` は、2ページ目以降の、各ページの最初の位置です。`block` は、Markdownの最上位のブロック(見出し・段落・リスト・表・コード・図など。0始まり)の番号で、`kind` が、ブロックの先頭(`start`)・段落などの途中(`text`。`offset` は、空白を除いた文字数)・表の行(`row`)・コードの行(`line`。`index` は行の番号)を表します。`snippet` は、そのページの最初の文字です。

エラー時は `{"error": {"code": "...", "message": "..."}}` を返します(400: 不正なリクエスト / 413: サイズ超過 / 500: PDF生成失敗)。`GET /healthz` は稼働確認用です。

## 構成と開発

- このアプリ(`app/`)は、composeの1サービスです(他に、`ocr-rag`・`postgres`・`ollama`)。Express が、ビルド済みの画面(React + `@mdxeditor/editor`。HTMLの解析に `parse5`、図の描画に `mermaid`)の配信と、`POST /api/pdf`・`POST /api/layout` を提供します。
- PDF生成は、要求ごとにChromiumを起動・終了します(常駐させません)。同時に複数の要求が来た場合は、順番に処理します。描画するHTMLは、JavaScript無効・外部通信遮断の状態で処理します(Mermaidの図を作るときだけ、図の描画用の別ページでJavaScriptを使います。実行されるのはMermaid本体だけで、外部通信は遮断し、PDFにするページは、JavaScript無効のままです)。
- 起動時にPDFを1本生成し、Mermaidの図を1つ描画して、Chromiumとフォント・図の描画が使えることを確認します。失敗した場合はコンテナが終了します(`docker compose logs app` で原因を確認できます)。
- コンテナは、非root・読み取り専用ルート・全Capability削除で動きます。

テストは、Dockerの `test` ステージで実行します(型チェック → ビルド → 全テスト。実Chromiumを使う、PDF生成と画面操作の結合テストを含みます)。

```bash
docker build --target test -t rag-pdf-studio-app:test ./app
```
